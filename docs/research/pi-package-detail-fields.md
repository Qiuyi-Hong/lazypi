# Audit pi.dev package-detail fields against LazyPi data

## Summary
[Audit pi.dev package-detail fields against LazyPi data](https://github.com/Qiuyi-Hong/lazypi/issues/16) requests a field-by-field evidence audit, not a UI decision. The [example page](https://pi.dev/packages/@vanillagreen/pi-extension-manager?name=package+manager) displays manifest facts plus gallery-computed facts: LazyPi HEAD (`e114300`) has local installation facts and a subset of npm search/latest-manifest fields, but not downloads, license, size, peer counts, exact Pi manifest JSON, or README in its existing model. Remote publisher metadata is observed, **not** independently verified as safe or matching installed contents.

## Findings

1. **Claim:** At fetch time the page showed package `@vanillagreen/pi-extension-manager`, version `3.0.1`, published `Sep 21, 2026`, downloads `672/mo · 62/wk`, author `vanillagreencom`, license `MIT`, type `extension`, size `318.8 KB`, and `0 dependencies · 4 peers`. These values are a snapshot, particularly downloads. **Sources:** [pi.dev page](https://pi.dev/packages/@vanillagreen/pi-extension-manager?name=package+manager), [npm latest version manifest](https://registry.npmjs.org/%40vanillagreen%2Fpi-extension-manager/latest). **Support:** direct observation, not independent metadata validation. **Confidence:** high for returned content; low for future values/provenance.
2. **Claim:** Pi supports explicit `pi.extensions`, `skills`, `prompts`, `themes` or conventional directories, optional gallery `pi.image` and `pi.video`, and npm gallery discovery using the `pi-package` keyword. Pi warns that packages can execute code. **Sources:** [official Pi package docs](https://pi.dev/docs/latest/packages). **Support:** direct evidence. **Confidence:** high.
3. **Claim:** npm full package metadata has per-version publish times in `time`, while download counts are available through separately documented rolling-period endpoints; neither is the HEAD adapter's `/latest` lookup. **Sources:** [npm package metadata documentation](https://github.com/npm/registry/blob/main/docs/responses/package-metadata.md), [npm download-count API documentation](https://github.com/npm/registry/blob/main/docs/download-counts.md), [HEAD community adapter](https://github.com/Qiuyi-Hong/lazypi/blob/e114300/src/community.ts). **Support:** direct evidence for documented fields and code; **researcher inference** for reproducing pi.dev presentation. **Confidence:** high for API existence, low for exact gallery computation.

### Field-by-field audit

**Legend:** Local = configured inventory and installed package manifest; cache = prior search or per-package metadata persisted in `<agent-dir>/lazypi-cache.json`; API = existing HEAD public npm search or `/{name}/latest` request, **not a proposed request**. Every local/code column is based on worktree [packages.ts](https://github.com/Qiuyi-Hong/lazypi/blob/e114300/src/packages.ts), [community.ts](https://github.com/Qiuyi-Hong/lazypi/blob/e114300/src/community.ts), [ui.ts](https://github.com/Qiuyi-Hong/lazypi/blob/e114300/src/ui.ts), and [architecture.md](https://github.com/Qiuyi-Hong/lazypi/blob/e114300/docs/architecture.md), read in the isolated worktree; displayed/raw example values are from the [page](https://pi.dev/packages/@vanillagreen/pi-extension-manager?name=package+manager) and [npm latest response](https://registry.npmjs.org/%40vanillagreen%2Fpi-extension-manager/latest). Capability does **not** mean the example is installed or cached here.

| Page field / section | Locally obtainable | Existing cache / API | Missing, offline, or qualification |
| --- | --- | --- | --- |
| Name; short description | Installed manifest `name`, `description`; fallback source-derived name | Search/latest name and description, cached if previously fetched | Missing install means no local description. Publisher text is not verified. |
| Install command; package identity | Configured source, installed path, scope (`user`/`project`); identity handles npm pins | Remote source constructed `npm:${name}` | Page's install command does not establish local installation. |
| Version | Installed version if local manifest exists | Search or latest version; cached copy may be stale | Never conflate installed with remote latest. Offline without cache has no latest. |
| Published | No local publish timestamp | Adapter maps `pkg.date` when supplied and caches `published` | Example `/latest` response has **no `date`**, so fresh HEAD details cannot derive its page date from this endpoint. Full npm metadata `time[version]` would require a different request. |
| Downloads (month/week) | None | Neither HEAD adapter nor cache holds counts | npm has a separate downloads API; no evidence exact pi.dev rolling window matches an endpoint. |
| Author | Local manifest string/object `.name` | Adapter selects `author.name`, else `publisher.name` | Example page says `vanillagreencom`; raw latest `author.name` is `vanillagreen`, `_npmUser.name` is `vanillagreencom`. HEAD would use `vanillagreen`. |
| License | Raw installed manifest may contain it; local parser discards it | Example raw latest says `MIT`; adapter/cache discard license | Cannot currently show license through either LazyPi model. |
| Types / declared resource kinds | Local parser tests explicit `pi` arrays or directory existence; inventory has type names | Adapter records names of nonempty declared `pi` arrays only | Remote empty type list means **unknown**, not confirmed none; implicit directory discovery absent remotely. Local resource list is not a verified list of actually loaded files after filters. |
| Size | No local computed size | Example latest `dist.unpackedSize` is `326481` bytes; adapter discards it | Page `318.8 KB` is numerically consistent with KiB rounding (**inference**), but exact gallery rule not verified. |
| Dependencies and peers | Raw local manifest may contain both; local parser discards them | Adapter holds up to 30 dependency **names**, no peer fields/count; example raw latest has four peer entries, no runtime dependencies map | An empty adapter dependencies list is shown as `unknown`, not zero. No ranges, tree, or peer count. |
| Pi manifest JSON; image | Parser checks resource arrays but discards paths, image | Raw latest contains `pi.extensions` and `pi.image`; adapter keeps only kind names | Existing LazyPi models do not retain exact JSON, paths, or preview image. |
| Security note | Not a package metadata field | Community rows are labeled `unverified` | Official Pi warning applies generally; metadata does not prove safety. |
| README / embedded animated image | HEAD does not read installed README | Latest adapter does not fetch/store README | Page content is unavailable in existing model; separate local read or remote content would be needed. |
| Repository / homepage | Local manifest extracts repository URL, not homepage | Adapter extracts repository only; example raw latest has both | Publisher-asserted repository URL does not prove correspondence. |
| Local-only scope/state/error | HEAD inventory derives enabled, disabled, custom, shadowed, missing and manifest error | Remote records cannot know these | Missing configured path has no local manifest; bad manifest reports error rather than invented detail. |

**Rendering and absence (direct local evidence):** [HEAD community.ts](https://github.com/Qiuyi-Hong/lazypi/blob/e114300/src/community.ts) searches `keywords:pi-package` (30 results, actual keyword post-filter), stores search and details with a one-hour TTL, and may return older cache values. `PI_OFFLINE=1` uses cache only; uncached detail throws `Offline: package details not cached`. Registry update-check failures preserve cached versions. [HEAD ui.ts](https://github.com/Qiuyi-Hong/lazypi/blob/e114300/src/ui.ts) renders local source/scope/state/version/resources/repository/author and, for remote rows, latest/provides/repository/author/published/dependency names; Enter calls the details loader. Empty remote resources/dependencies render as unknown, and Community shows `unverified`. [HEAD packages.ts](https://github.com/Qiuyi-Hong/lazypi/blob/e114300/src/packages.ts) marks uninstalled configured entries `missing` and surfaces invalid manifests. [Architecture](https://github.com/Qiuyi-Hong/lazypi/blob/e114300/docs/architecture.md) summarizes this design; code is the precise contract.

**Separate dirty main checkout:** The file inspected at `/Users/qiuyihong/Projects/lazypi/src/community.ts` differs from this worktree's HEAD: it defines `UpdateSnapshot` and `cachedUpdates(items)`, and returns cached version snapshots from `checkUpdates()` even in offline mode. This changes **update-view cache availability** on that live path only; it adds none of the omitted detail fields or publication-time retrieval. No git operation was used; this is a direct file-read comparison. Cite HEAD links above for checked-in behavior; dirty file has no stable remote citation.

## Contradictions
- Page author `vanillagreencom` versus latest manifest `author.name = vanillagreen` (and `_npmUser.name = vanillagreencom`): likely distinct publisher versus author attribution (**inference**), not grounds to silently substitute either. [Page](https://pi.dev/packages/@vanillagreen/pi-extension-manager?name=package+manager); [raw manifest](https://registry.npmjs.org/%40vanillagreen%2Fpi-extension-manager/latest); [adapter](https://github.com/Qiuyi-Hong/lazypi/blob/e114300/src/community.ts).
- Page publication date versus `/latest` manifest with no `date`: architecture's broad mention of publish metadata is conditional on its presence; HEAD `pkg.date` cannot reproduce this example's page date from fresh details. [Page](https://pi.dev/packages/@vanillagreen/pi-extension-manager?name=package+manager); [raw manifest](https://registry.npmjs.org/%40vanillagreen%2Fpi-extension-manager/latest); [npm full metadata docs](https://github.com/npm/registry/blob/main/docs/responses/package-metadata.md).

## Missing evidence
- No installed manifest/settings/cache for this particular example package were inspected: all local/cache availability is **conditional**, not a claim of actual local presence. No offline run was performed; offline behavior is read from code.
- No authoritative first-party derivation of pi.dev's size, author-selection, or download-window calculation; page values are volatile. Publisher-controlled manifest/README is not an independent security or source audit.
- Page, ticket, Pi docs and npm latest were directly reachable; no source-access failure. Automated `source_check` yielded **unclear** because semantic support/contradiction assessment was unavailable; first-party response bodies were inspected directly instead.
