# Verify Pi overlay constraints and theme-aware reference patterns

## Summary
Pi can center a width-constrained custom overlay, but `maxHeight` is a **top-slice, not a scroll viewport**: a too-tall popup loses its footer and bottom border. The transferable reference is hierarchy (compact list, subdued metadata, visible selection, bounded detail and chrome), not the other manager's hard-coded ANSI colors or narrow-screen column calculations. This is evidence for [Verify Pi overlay constraints and theme-aware reference patterns](https://github.com/Qiuyi-Hong/lazypi/issues/17), not a UI proposal.

## Findings

1. **Claim:** Pi resolves overlay `width` (absolute columns or percentage of full terminal width), applies `minWidth`, then clamps to remaining width after margins; default is at most 80 columns. `maxHeight` likewise resolves from terminal rows and clamps to available height. The centered anchor positions using the resulting visible height. **Sources:** [Pi TUI implementation](https://github.com/earendil-works/pi/blob/main/packages/tui/src/tui.ts), [Pi TUI docs](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/tui.md). **Support:** direct evidence. **Confidence:** high for inspected source; installed-version parity with GitHub `main` not verified. **Inference:** a requested fixed width cannot guarantee that many columns on a narrower terminal; layout must use the width actually passed to `render(width)`.
2. **Claim:** Pi calls `component.render(resolvedWidth)` and, if output exceeds `maxHeight`, takes `overlayLines.slice(0, maxHeight)` before positioning/compositing. Its own `/overlay-maxheight` example expects the lower lines **and bottom border to be cut off**. There is no automatic vertical scrolling from `maxHeight`; Pi documents `ScrollView` as a separate viewport component, while the QA streaming example explicitly slices a fixed-size window and handles up/down input itself. **Sources:** [TUI source](https://github.com/earendil-works/pi/blob/main/packages/tui/src/tui.ts), [first-party QA example](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/examples/extensions/overlay-qa-tests.ts), [TUI guidance](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/tui.md). **Support:** direct evidence. **Confidence:** high. **Inference:** reserve rows for border/footer and manage content viewport/selection within the overlay's actual height; merely raising `maxHeight` does not make oversized content navigable.
3. **Claim:** Every rendered line must fit the supplied width in **visible columns** (ANSI, wide Unicode, emoji matter); Pi recommends `visibleWidth`, `truncateToWidth`, `sliceByColumn`, and `wrapTextWithAnsi`. Pi theme roles include `accent`, `border*`, `text`, `muted`, `dim`, `success`, `warning`, `error`, `selectedBg`, and scrollbar colors; the active callback theme should drive styling, with invalidation for cached ANSI. **Sources:** [Pi TUI guidance](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/tui.md), [theme roles](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/themes.md). **Support:** direct evidence. **Confidence:** high. **Inference:** map visual intent to Pi's semantic roles rather than copying a fixed RGB/ANSI palette; check contrast in both dark/light and terminal defaults.
4. **Claim:** At this worktree's `e114300`, LazyPi asks for a centered `width: 120, maxHeight: 26` overlay. `ManagerPopup` frames at `render(width)` with one border column each side, no horizontal interior padding; it emits title, all eight section labels in one joined line, search/filter, body, two hint lines and bottom border, truncating at width. It bounds the list by terminal rows (Packages up to 12 rows; other sections up to 7), and on sufficiently wide Packages/Extras renders an adjacent inspector; Enter replaces the list with detail. **Sources:** [local overlay call](https://github.com/Qiuyi-Hong/lazypi/blob/e114300/extensions/lazypi.ts), [local renderer](https://github.com/Qiuyi-Hong/lazypi/blob/e114300/src/ui.ts). **Support:** direct evidence. **Confidence:** high. **Inference:** `maxHeight: 26` does **not** prove footer visibility: at 24 terminal rows Pi caps to 24, while the renderer may emit more (especially Extras' multi-line rows/group headings, expanded detail, error lines). Likewise eight labels can be cut mid-navigation when narrower. Earlier [reference note](https://github.com/Qiuyi-Hong/lazypi/blob/e114300/docs/research/pi-extension-manager-tui.md) describes an older 78-column layout; prefer the inspected worktree for present-state comparison.
5. **Claim:** The published extension-manager browser at [commit `8222af2`](https://github.com/vanillagreencom/kendex/tree/8222af276277d3461b8a7ebf0c9ffdd1c9a0384f/pi-extensions/pi-extension-manager) uses a centered `92%` width / `85%` max-height overlay, two-column list/inspector, padded frame (`POPUP_PADDING_X=2`, `Y=1`), a search line, filter/action strip, divider, list title/count, selected row background, inspector identity/state/description then labeled metadata, and a low-emphasis footer. Its list viewport uses a bounded item count and earlier/more markers; diagnostics have their own scroll offset. `render.ts` wraps longer text and caps frame body with a `↓ more line(s)` indicator. **Sources:** [browser composition](https://github.com/vanillagreencom/kendex/blob/8222af276277d3461b8a7ebf0c9ffdd1c9a0384f/pi-extensions/pi-extension-manager/extensions/manager/manager-ui.ts), [frame/semantic helpers](https://github.com/vanillagreencom/kendex/blob/8222af276277d3461b8a7ebf0c9ffdd1c9a0384f/pi-extensions/pi-extension-manager/extensions/manager/render.ts), [layout constants](https://github.com/vanillagreencom/kendex/blob/8222af276277d3461b8a7ebf0c9ffdd1c9a0384f/pi-extensions/pi-extension-manager/extensions/manager/types.ts). **Support:** direct evidence. **Confidence:** high. **Inference:** interior whitespace, strong identity/selection, subdued scope/source, content-first viewport and bounded hints are transferable *patterns*, not proof the whole two-pane layout fits LazyPi.
6. **Claim:** Do **not** transfer this browser's low-width or color implementation verbatim: its `leftWidth` has a floor and `rightWidth = max(20, width-leftWidth-3)`, so the composed columns can exceed available content width on narrow terminals, subsequently truncated by the frame. `manager-ui.ts` uses `ansiRed`/`ansiYellow` for badges and hints and `render.ts` uses `ansiGreen` for frame title; [`format.ts`](https://github.com/vanillagreencom/kendex/blob/8222af276277d3461b8a7ebf0c9ffdd1c9a0384f/pi-extensions/pi-extension-manager/extensions/manager/format.ts) fixes these to ANSI 31/33/32 despite other theme-aware helpers (`selectedBg`, `accent`, `muted`, `dim`, `borderAccent`). **Sources:** [browser](https://github.com/vanillagreencom/kendex/blob/8222af276277d3461b8a7ebf0c9ffdd1c9a0384f/pi-extensions/pi-extension-manager/extensions/manager/manager-ui.ts), [render helpers](https://github.com/vanillagreencom/kendex/blob/8222af276277d3461b8a7ebf0c9ffdd1c9a0384f/pi-extensions/pi-extension-manager/extensions/manager/render.ts), [ANSI definitions](https://github.com/vanillagreencom/kendex/blob/8222af276277d3461b8a7ebf0c9ffdd1c9a0384f/pi-extensions/pi-extension-manager/extensions/manager/format.ts). **Support:** direct evidence + arithmetic interpretation. **Confidence:** high. Package/extension inventory semantics differ; [existing research](https://github.com/Qiuyi-Hong/lazypi/blob/e114300/docs/research/pi-extension-manager-tui.md) covers that distinction.
7. **Claim:** Official LazyVim presents a strong brand header and separated task-oriented keys in its [Snacks dashboard config](https://github.com/LazyVim/LazyVim/blob/main/lua/lazyvim/plugins/ui.lua), but its [configuration](https://github.com/LazyVim/LazyVim/blob/main/lua/lazyvim/config/init.lua) selects a colorscheme (`tokyonight` by default), and [colorscheme specs](https://github.com/LazyVim/LazyVim/blob/main/lua/lazyvim/plugins/colorscheme.lua) integrate theme-provided highlights across UI plugins. Its [README screenshots](https://github.com/LazyVim/LazyVim/blob/main/README.md) are illustrative, not a terminal popup dimension specification. **Support:** direct evidence; **Confidence:** high. **Inference:** restrained brand heading, grouped navigation/actions, and theme-dependent emphasis transfer; pixel colors, font icons, Neovim-specific highlights and dashboard geometry do not define Pi overlay behavior.

## Contradictions
- Earlier [extension-manager research](https://github.com/Qiuyi-Hong/lazypi/blob/e114300/docs/research/pi-extension-manager-tui.md) says LazyPi requested width 78/max height 26 and lacked a persistent inspector; the **inspected worktree** requests 120 and already has a conditional inspector. The older note is historical context, not current implementation evidence.
- No contradiction in Pi's API: `maxHeight` means a size ceiling; content scrolling is a separate responsibility.

## Missing evidence
- No live terminal/resize/theme trial or exact installed `@earendil-works/pi-tui` implementation version comparison against linked upstream `main`; local installed docs and QA example were read. Actual worst-case popup heights and accessibility/contrast remain unmeasured.
- LazyVim official source supplies qualitative cues, not a canonical Pi padding or color mapping. Reference package pin is the previously documented published 3.0.1 source commit, not an assertion that its current release is identical.
